## Architecture

- `SnowGlobeWorld` owns persistent agent records, resources, stockpiles, structures, event history, validation, commit, and deterministic digests.
- `ISnowGlobeInferenceAdapter` receives an immutable `SnowGlobeObservation` and returns a proposed action. It cannot mutate or retain the world through the interface.
- `SequentialInferenceScheduler` is the baseline: it observes, awaits one proposal, validates, and commits in stable agent-ID order. It records queue/inference/proposal/accept/reject metrics.
- `ScriptedInferenceAdapter` is the offline baseline. The fixed seed run has eight agents gather wood and stone, build a shelter and storage asset, then maintain the shelter.
- The event log records committed actions only. Invalid proposals return a rejection result and do not alter resources, structures, agents, or the event log. Replaying the canonical event sequence produces the same state and event digests.

## Run-store interruption and replay experiment

`SnowGlobeRunStore` creates local-only, single-writer `snow_globe_run_store/v5` artifacts. Strict bounded v2 and v3 reading/reconstruction remain supported as flat legacy inputs, but legacy directories are never upgraded or opened for append. Explicit v4 remains appendable through its frozen framed contract. V4 and v5 retain the exact `snow_globe_participant_command/v1` identity and store each admitted command plus receipt as one compound, checksum-bound `ParticipantEvaluation` record at a tick boundary. Accepted events still replay through the deterministic validator; stale and domain-rejected evaluations reconstruct the same bounded idempotent receipt without becoming world authority. New v5 participant evaluations are valid only while the durable pause state is paused; v4 participant behavior is unchanged.

V4 and v5 ledger payloads are bounded append-only JSONL segments. A separate bounded marker segment writes a checksum-linked prepare before each payload and a commit marker afterward. Each scheduled prepare binds the full payload and the length/checksum of every independently flushed scheduled-payload prefix (at most four complete-record chunks). Scheduled interruption recovery recognizes only one of those prepared prefixes, then validates every complete record's inner checksum, sequence, and deterministic schedule; any other or partial residue (including malformed UTF-8, NUL, or arbitrary bytes) fails closed. An ordinary `Read` exposes only committed frames and remains side-effect-free. `OpenForAppend` may resolve one final interrupted scheduled-tick frame: an incomplete prepared prefix is abandoned at the prior checkpoint, while a complete checksum-valid frame is adopted only after the disposition is durably recorded in a checksum-valid continuation marker. Recovery never truncates or rewrites the source ledger or marker bytes; the continuation binds the full source ledger and marker lengths plus whole-file checksums. A second recovery, participant-command tail, corrupt committed history, broken/forked link, unknown tail/artifact, or global framing/capacity overflow across all segments fails closed. Participant records are never inferred, ignored, or repaired.

V5 adds one `PauseTransition` record/frame with stable wire kind `6`, action exactly `Pause` or `Resume`, and the exact current tick/state/event identity. It does not mutate deterministic world state, events, revision, or digests. Reconstruction starts running and accepts only alternating, non-redundant transitions at frame/ledger boundaries. A well-framed uncommitted pause transition uses the same single continuation budget as scheduled recovery and is always abandoned at the prior durable pause state after any complete payload is fully validated. A partial/noncanonical pause payload or commit tail fails closed; a fully committed transition restores without a continuation. The recovery maximum remains one continuation and two total segments.

Only `OpenForAppend` under the single-writer lease may create the recovery continuation. Its pre/post-lease comparison binds the raw header and every segment byte. Public `CreateNew` accepts v5 only; `OpenForAppend` accepts explicit v4 and v5. The physical filesystem and deterministic fault-injection adapters are internal to the RunStore module, so callers cannot manipulate frames or recovery controls. Deterministic tests cover ordinary restart at before-write, prepared-prefix mid-payload, pre-commit, and commit-readback windows. A real partial filesystem write is corruption and is not recoverable. This is not power-loss certification, filesystem/hardware durability proof, cross-host coordination, general transactions, or an exactly-once claim.

An accepted snapshot sets `IsPaused=true` solely to denote an inert inspection projection, not durable or historical pause evidence.
