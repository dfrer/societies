# Snow Globe Provider Readiness Live Evidence Outcome Contract

## User outcome and cleared gate

- Add the smallest reviewed invocation and atomic-retention surface for the merged provider-readiness Adapters, then use it once from exact merged source to record current raw-free OpenRouter and Ollama readiness evidence.
- Produce and validate one canonical v2 current-readiness assessment from those two observations. The assessment must continue to report primary-attempt state `unknown`, routing `not_issued`, and null routing input.
- Preserve the accepted cognition result (`openrouter_default`) as a quality recommendation only. Current readiness evidence does not grant dispatch, payment, proposal, gameplay, or world authority.

## Implementation scope

- Keep code inside the Snow Globe lab and the smallest dedicated or existing CLI/test projects. Keep artifacts under `artifacts/snowglobe/provider-readiness/` and milestone documentation in the established repository-truth files.
- Expose one deep, one-shot command that invokes the already reviewed provider-neutral Module through the fixed OpenRouter and Ollama production Adapters, creates both canonical observations, creates the canonical v2 assessment, validates all three, and publishes them atomically to fixed milestone paths.
- OpenRouter must use the existing stored credential seam without accepting a secret in arguments or environment variables. It performs at most one reviewed Adapter invocation: exactly three sequential authenticated metadata GETs on success, no POST/completion, retry, fallback, or alternate.
- Ollama accepts only the minimum non-secret runtime identity needed by the reviewed pinned verifier, revalidates the exact registered process/listener/model contract, and performs at most one loopback `GET /api/tags`. It performs no generate, pull, update, retry, fallback, or alternate.
- Publish strict raw-free evidence only. Fixed CreateNew/atomic semantics must refuse overwrite, partial reuse, ambiguous publication, symlink/reparse/hardlink escape, and a second governed invocation. Failure or uncertain publication leaves a closed terminal/tombstone result and never retries.
- CLI output is a closed summary containing status, request counts, artifact digests, assessment status, and fixed paths only. Never emit credentials, account identity, raw metadata, response bodies, host paths, PID/start ticks, dynamic errors, or provider content.

## Non-goals

- Do not implement a durable routing-attempt ledger, `NotStarted` claim, dispatch permit, provider execution, completion request, proposal, benchmark, model generation, gameplay integration, deployment, or commercial path.
- Do not change the accepted provider comparison, quality scores, routing policy, proposal schema, financial journal, credential format, provider/model/Azure/ZDR pins, or `src/societies/`.
- Do not add credential administration, API-key arguments, environment-key reads, retries, parallel provider calls, redirects, proxy support, arbitrary output paths, overwrite behavior, or a general-purpose provider-health command.
- Do not claim continuous/future readiness, execution authenticity beyond the observation contract, general intelligence, gameplay quality, price-performance, deployment readiness, or commercial readiness.

## Acceptance criteria

1. The CLI surface is versioned, one-shot, fixed-path, and raw-free; its interface cannot authorize provider completion or accept credentials.
2. Offline tests prove exact OpenRouter 3-GET/no-POST and Ollama 1-GET/no-generate behavior through deterministic fake transport/runtime seams.
3. Tests cover no arguments/extra arguments, malformed runtime identity, missing credential, provider unavailable, timeout/cancellation, partial and ambiguous publication, existing targets, path/reparse/link attacks, second invocation, stale observation, assessment validation, and secret-free output.
4. Red-first implementation receives `security_worker` ownership and independent `deep_reviewer` review with no unresolved P0-P2 findings.
5. The implementation is delivered and merged with required checks before any credential, provider, process/listener, network, or live-state action.
6. From exact merged source, one governed sequential live command runs once. No stage or provider Adapter is rerun regardless of result.
7. Retained artifacts validate canonically and record exact source commit, contract digests, request counts, result status, observation limits, and artifact hashes without secrets or raw provider metadata.
8. Independent evidence review reports no unresolved P0-P2 findings; `CURRENT_BUILD.md`, `WORKFLOW.md`, README, and this contract state exactly what was proven.

## Evidence and validation

- Capture a focused compile/behavioral red before production code, then run the identical focus green.
- Run focused CLI/store/Adapter tests, full Snow Globe Release, existing OpenRouter CLI/security and Recording CLI suites, relevant Release builds, canonical artifact validation, secret-like scans, and `git diff --check`.
- Before live invocation verify exact merged source, clean worktree, fixed targets absent, stored-credential seam available without reading/exporting the secret, current Ollama process/listener identity, and no already-consumed readiness invocation.
- Live action is one sequential command only. OpenRouter and Ollama Adapters are each invoked at most once; no retry, substitute, second attempt, completion, or paid generation is permitted. Stop and retain the closed result on any terminal or uncertain outcome.
- After live invocation, inspect only canonical raw-free artifacts and closed CLI output. Validate locally once. Do not inspect raw provider responses, credentials, account details, or dynamic errors.

## Delivery boundary

- The main task owns outcome, documentation, integration, preflight, live invocation, evidence inspection, full validation, Git/PR delivery, required-check waiting, merges, and final repository-state reporting.
- One bounded `security_worker` owns CLI/store/tests and focused validation. It must not stage, commit, access credentials/live state, invoke providers, or spawn workers.
- One independent `deep_reviewer` reviews the complete implementation diff before delivery and the retained evidence/docs before final delivery.
- Deliver the offline invocation surface through a reviewed `codex/` pull request and merge it before live action. From the merge, run the single governed cycle, then deliver the retained evidence and final milestone documentation through a second reviewed pull request and required checks.
